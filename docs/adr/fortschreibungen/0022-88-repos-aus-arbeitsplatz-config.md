# Fortschreibung #88 (2026-11-02): Claim, Ticket-Auswahl und Haupt-Sync lösen Repos über die Arbeitsplatz-Config auf

Ergänzt [ADR 0022](../0022-dark-factory-kern-und-verteilung.md) (Betriebsart Arbeitsplatz, factory#87); die Fortschreibung steht als Datei (siehe [Fortschreibung zu ADR 0013](0013-1860-fortschreibungen-als-dateien.md)).

- **Entscheidung (Repos aus der Config, nicht aus dem Arbeitsverzeichnis):** Im Arbeitsplatz ist das Arbeitsverzeichnis kein Git-Repo. `ticket-lock`, `claims-pruefen`, `naechstes-ticket` und `haupt-sync` fragen git darum je Repo des Blocks `arbeitsplatz` der Projekt-Config (`gitOrteAus` in `scripts/worktree-aufraeumen.mjs`: ein Ort je Repo mit `cwd` gleich Repo-Pfad); eingebettet ist es ein Ort ohne `cwd`, und das Verhalten bleibt zeichen- und aufrufgleich. Der Name im Ticket (`arbeitsplatzPfade`) heißt seit factory#87 `arbeitsplatzAus`; es gibt keinen Alias.
- **Vereinigung über die Repos:** Branches (lokal und Remote) und Worktrees aller Repos werden vereinigt (`registrierteWorktreesJeRepo`, `refsJeRepo`, `belegungJeRepo`). Ein Worktree `<praefixe.worktree><nr>` in Repo B belegt die Nummer, auch wenn Repo A keinen hat; `ticket-lock` nimmt als Lebenszeichen das Maximum über alle Worktrees und Branch-Köpfe der Nummer, `git log` läuft im Repo des Branches.
- **Fail-closed nur bei `for-each-ref` und `worktree list`:** Scheitert eines davon in einem Repo, bricht der Lauf mit `git <args> scheiterte in Repo <name> (<pfad>): <erste Zeile>` und einer `Fix:`-Zeile ab (Exit 2), statt mit den übrigen Repos weiterzumachen: eine unvollständige Belegung würde ein belegtes Ticket freigeben. `fetch` bleibt je Repo fail-open (offline zählen die lokalen Remote-Refs). Eingebettet wird ein git-Fehler unverändert weitergereicht.
- **Lock-Ort im Arbeitsplatz unter der Wurzel:** `<wurzel>/.claude/<praefixe.worktree>locks` (`lockVerzeichnisFuer` in `scripts/ticket-lock-lib.mjs`), nicht im git-common-dir eines Repos, weil ein Ticket nicht an ein Repo gebunden ist und das Arbeitsverzeichnis kein Repo ist. Eingebettet bleibt der Lock im git-common-dir. Es gibt im Arbeitsplatz keine Bestands-Locks, eine Migration entfällt.
- **`pfadErlaubt`:** Im Arbeitsplatz gilt ein Worktree nur direkt im Worktree-Ordner des Repos, das ihn registriert hat (`worktreeOrdner` aus der Auflösung); der Ordner eines anderen Repos, eine tiefere Ebene, ein Lens-Name und eine fremde Nummer werden abgelehnt. `worktree remove` und die Nachprüfung laufen im Repo des Worktrees.
- **Grenzen von `claims-pruefen`:** Je Lauf wird pro Claim ein Worktree geführt (der erste in Config-Reihenfolge); hat ein Ticket Worktrees in zwei Repos, räumt der nächste Lauf den Rest ab, weil die geschlossene Issue weiter als lokale Spur gilt. Das `--json`-Dokument bleibt unverändert.
- **Grenze von `naechstes-ticket`:** Offene PRs fragt das Skript nur im Repo `repo` der Config, weil `arbeitsplatz.repos` kein `owner/name` trägt; die Branches der anderen Repos zeigen sich nach dem `fetch` als Remote-Refs.
- **Haupt-Sync je Repo, ohne Sitzungsbasis:** Mit Block `arbeitsplatz` in der Config von `CLAUDE_PROJECT_DIR` hebt `haupt-sync` jedes Repo für sich per Fast-Forward (`fuehreArbeitsplatzSyncAus`); Ausgabe mit `Repo <name>:`, `--streng` liefert Exit 1, sobald ein Repo abweicht. Ein fehlender Pfad oder ein git-Fehler in einem Repo ist eine Notiz mit `Fix:`-Zeile, die übrigen Repos werden trotzdem gehoben (der SessionStart-Hook bleibt fail-open). Es gibt keine `Sitzungsbasis:`-Zeile, weil der Harness dort nicht per Repo-Pull kommt; der Ticket-Skill behandelt das Fehlen fail-closed. Ein Projekt-Repo trägt keinen Harness, darum entfallen das Ordnen der Harness-Änderungen und die Config-Neuprüfung. Ein kaputter Block ergibt eine Notiz mit Fix-Zeile; eine fehlende oder nicht lesbare Config bleibt eingebettet (fail-open wie bisher).
- **Standardzweig je Repo (Teil-Kriterium aus dem Sammelticket factory#101, Zeile L12):** `arbeitsplatz.repos[].standardzweig` ist optional, Default `main` (`standardzweigVon`). Das Feld steht in der Auflösung nur, wenn es gesetzt ist. Es steuert `haupt-sync` (`origin/<zweig>` für Rückstand und Fast-Forward; ein anderer ausgecheckter Zweig wird gemeldet) und `node scripts/arbeitsplatz.mjs worktree` (Basis `origin/<zweig>`). Das Muster ist ein einfacher Zweigname ohne Leerraum, Shell-Zeichen, `..` und `.lock`-Ende, weil der Wert in einem Befehlstext steht. Der eingebettete Befehl in `AGENTS.md` bleibt literal `origin/main` (ein Wächter verlangt Zeichengleichheit mit `worktreeBefehl`); eingebettet gibt es keinen Config-Schlüssel dafür.
- **`merge-testabgleich.mjs` bleibt unverändert:** Es läuft im Ticket-Worktree, und `git rev-parse --show-toplevel` löst einen verknüpften Worktree in beiden Betriebsarten auf; es liest nie das Arbeitsverzeichnis des Arbeitsplatzes.
- **Offen (eigene Zeilen):** `worktree-guard-hook.mjs` und `lens-auftrag-guard.mjs` tragen je einmal `origin/main` und sollen `standardzweigVon` nutzen (factory#89); der Ticket-Skill ruft `git fetch origin` und den Sitzungsbasis-Vergleich im Arbeitsverzeichnis und braucht für den Arbeitsplatz eine ausdrückliche Definition (Sammelticket factory#127).
