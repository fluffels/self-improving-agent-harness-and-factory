# Umsetzer: Guard-Proben (Negativtest, Red-Green, Anker-Selbstcheck)

Bedingte Datei des Umsetzers (Kern: `.claude/agents/factory-umsetzer.md`): lies sie, sobald dein Diff Guard- oder Gate-Code, eine neue Regex oder einen neuen Test enthält oder `node scripts/anker-liste.mjs` mindestens einen Anker nennt.

**Negativtest und Red-Green (Schritt 2):** Jede neue Regel in Guard- oder Gate-Code bekommt vor dem Review ihren eigenen Negativtest, der genau diese Regel verfälscht. Jeder neue Test bekommt seine Red-Green-Probe nach AGENTS.md § Tests gegen False Positives absichern: den Anker vorher auf genau einen Treffer zählen, die geprüfte Eigenschaft testweise brechen, Rot sehen, zurücksetzen. Ein Rot zählt nur, wenn der Test genau an dieser Eigenschaft scheitert (ein Test, der „im selben Takt“ behauptet, ist vakuös, wenn `exec` den Takt selbst hochzählt). Mehrere Guards sabotierst du nach dem Zwischen-Commit per Scratchpad-Skript (Anker zählen, ersetzen, Test fahren, in `finally` zurückschreiben), nie per `git checkout`.

**Anker im Selbstcheck (Schritt 4):** Zum Block `Selbstcheck:` gehört je Anker der Guard-Liste (`node scripts/anker-liste.mjs` vor dem Selbstcheck) einzeln der Test, den eine Sabotage rot macht, oder `n.a.` mit Grund; eine Sammelangabe über eine Anker-Art, etwa „catch-Zweige n.a.“, gilt nicht: je catch-Zweig der Test seines Negativfalls oder `n.a.` mit Grund. Je Regex fährt der Selbstcheck vorab den Vollsweep über jede Komponente (Anker, Klasse, Quantor, Alternative, Gruppe) beidseitig, schon in Runde 1, und protokolliert jede Sabotage-Probe als `<datei> | <Suchstring> → <Ersatz> | <Test> | Ergebnis` (bei `rot` nennt das Ergebnis die Sabotageform, wenn mehrere möglich sind, etwa Entfernen oder Schlucken; „belegt durch den echten Lauf im Repo“ ist nur dann ein Beleg, wenn die Repo-Config den Pfad auslöst, sonst gilt die Sabotage-Probe; factory#263). Dazu die Zeile `Guard-Liste: <n> Anker, <m> belegt`. Meldet `node scripts/groessenstufe.mjs --pfade <geänderte und ungetrackte Pfade>` vor dem ersten Commit `SWEEP: stichprobe`, ersetzt die Stichprobenregel der Test-Brille den Vollsweep je Regex (factory#272).

**Zahl in einer Regel:** Eine Zahl in einer Regel als Konstante ableiten und die Konsumenten per Grep prüfen.
