# Sonderfälle unter Windows

Bedingte Datei des Umsetzers (Kern: `.claude/agents/factory-umsetzer.md`), auch für Lens und Hauptchat-Ablauf: lies sie vor Schritt 1 bzw. dem ersten Prozess- oder Skript-Aufruf, sobald `node -p process.platform` den Wert `win32` ergibt (Plattform-Weiche; Claude Code zeigt das als `Platform: win32` im Umgebungsblock). Auf jeder anderen Plattform brauchst du sie nicht.

Weitere Windows-Fälle: [Windows und Git-Bash: was geht beim Skripten verloren](../../../docs/agent-harness-faq.md#windows-und-git-bash-was-geht-beim-skripten-verloren) und [Worktree unter Windows entfernen](../../../docs/agent-harness-faq.md#wie-entferne-ich-einen-worktree-unter-windows-sauber-und-was-ist-mit-node_modules).

**Skripte und Heredocs:** „unexpected EOF“ bei einem Heredoc (auch bei kleinen Skripten mit Backslashes, der Bash-Wrapper halbiert jeden Backslash), CRLF durch Python unter Windows (`newline=''`) und ein verweigerter Dateiname mit „report“ haben ihren Ausweg in der FAQ (Skript per Write in den Scratchpad, `--body-file`). Das Write-Tool dekodiert `\uXXXX`: Escapes baust du per `String.fromCharCode(92)` und prüfst danach auf Nicht-ASCII; Anker mit Backslash legst du per Write ab und schreibst sie als `String.raw` (ein Heredoc halbiert sie). Testdateien und Fixtures mit Escapes oder Regex (`\n`, `\0`, `\r\n`, `\.`) entstehen nie aus einem Skript- oder Heredoc-String: ein Python-Heredoc macht aus `\n` einen echten Umbruch, jedes Skript halbiert die Backslashes, `sed` macht aus einem `\r\n` im Ersetzungstext echte Umbrüche.

**Prozesse:** Eine Probe per `execSync` mit Timeout lässt unter Windows den vitest-Prozessbaum zurück und sperrt den Worktree: Proben ohne `execSync`-Timeout fahren. Eigene Hilfsserver und Stubs (z.B. `python3 -m http.server`) beendest du per PID (`taskkill /PID <pid> /T /F` bzw. in Git-Bash `taskkill //PID <pid> //T //F`, nie per Name; `/T` beendet auch den `node.exe` unter einer `npx`-Hülle, [FAQ Falle 1](../../../docs/agent-harness-faq.md)). Das gilt für jeden Prozess. Ein `git show <ref>:<pfad>` bekommt in Git-Bash `MSYS_NO_PATHCONV=1` davor, sonst macht die Pfad-Umwandlung einen Windows-Pfad daraus. Der Exit-Code eines Skripts steht in PowerShell in `$LASTEXITCODE`, nicht in `$?`. Eine Ordner-Prüfung nach dem Entfernen ist `Test-Path <pfad>` (`False`: weg) bzw. in Git-Bash `test -e <pfad>`; ein `sed` mit Backslash-Ausdruck greift in Git-Bash still nicht (Edit-Tool nehmen).
